# Frozen TF-SN method specification

This is the canonical reproducible specification for the method family frozen
as AntMaze R74 and transferred without a decision-rule change as PointMaze
R15.  The specification revision is
`tfsn_frozen_cross_domain_r74_point_r15`.

The machine-readable setting inventory is
[`shared/frozen_r74_settings.json`](shared/frozen_r74_settings.json).  Historical
R11, R52, and R74 documents explain how the method was reached; they do not
override this specification.

## 1. Method boundary

TF-SN receives:

1. a goal-conditioned executor;
2. reward-free command-boundary trajectories from that executor;
3. a state projection `phi(s)` into the two-dimensional task space;
4. the primitive-step episode budget `T`; and
5. during evaluation, the observed binary task consequence used only as
   evidence and to switch from acquisition to return.

The domain adapter may define the state/action schema, load the executor, and
expose `phi`.  It may not add a distance threshold, wall rule, coordinate
rule, region list, candidate cap, horizon, or fallback policy.

The hidden goal coordinate, maze geometry, oracle paths, and benchmark success
radius are not planner inputs.  The success radius remains evaluator-only.
No task gradient update is made.

setting creates a new method revision.

coverage upper bound until the exact global argmax is certified.  There is no
top-k hub approximation or score cutoff.

R74/R15 does not call the older R11 consumptive-acquisition branch.  During
acquisition it selects a posterior hub and invokes the supplied-goal router;
after contact it invokes that same supplied-goal router on the evidence field.
The depth and beam settings remain declared because the shared base runtime
retains them, but they do not affect a frozen R74/R15 decision.

## 3. Reward-free preparation

### 3.1 Independent preparation seeds and collection

A preparation seed controls environment resets, command sampling, the grouped
train/validation split, and model initialization.  Seeds 0, 1, and 2 are
independent preparations.  PointMaze preparation seed `k` uses executor seed
`k`; AntMaze uses the one frozen E549-5M executor for every preparation seed,
so only TF-SN preparation randomness changes there.

Every seed has the same 36,000-command budget in either domain:

1. **Bootstrap (24,000):** 320 reward-free tasks of 75 commands.  Commands are
   sampled uniformly from the exact set of xy coordinates observed so far.
   No radius, nearest-neighbour rule, or spatial bin is used by this sampler.
2. **Acquisition alignment (6,000):** 80 tasks of 75 commands generated by the
   frozen R74/R15 acquisition controller.  Every observed task consequence is
   negative; no hidden goal or benchmark reward is present.
3. **Return alignment (6,000):** 80 tasks of 75 commands generated by the
   frozen supplied-goal router.  Its synthetic target is sampled uniformly
   from the occupied `sigma` cells of reward-free recorded support.  This is a
   preparation label only and is not a benchmark goal.

Task memory persists across physical resets inside one preparation task and is
cleared between tasks.  The physical episode has `H=T/tau` commands.  All
36,000 executed transitions enter consequence fitting and the recorded graph;
alignment data are not evaluation evidence.

### 3.2 Recorded road map

Execute the supplied policy in fixed `tau`-step commands.  Preserve every
command-boundary state and every executed transition as a recorded edge.
Recorded edges are never deleted.

The command horizon is always derived:

```text
H = T / tau,
```

and the protocol is invalid unless `T` is positive and exactly divisible by
`tau`.  Neither domain stores a separately chosen planning horizon.  In the
frozen evaluations, `T = 2000` and `tau = 100`, hence `H = 20` in both
domains.

### 3.3 Consequence model

Fit the shared three-member factorized mixture ensemble on reward-free
transitions.  A bridge is evaluated at every joint spatial/remaining-state
component mean, weighted by its joint mixture probability.  Endpoint sampling
is not used.  Ensemble values are reduced by the pessimistic minimum.

The deployed landing scale is

```text
sigma = held-out ensemble-and-mixture-weighted within-mode radial spatial spread
```

of the deployed consequence model.  It is recomputed whenever the executor or
consequence model is rebuilt; it is not copied from another domain or model.

### 3.4 Continuous reach measure

For recorded start `x`, commanded target `g`, and realized endpoint `x'`, set

```text
kappa_sigma(d) = exp(-d^2 / (2 sigma^2))
w_reach = (1 - kappa_sigma(||g-x||))
          (1 - kappa_sigma(||x'-x||)).
```

Near-zero requests and near-zero outcomes remain in the data but contribute
vanishing reach mass.  There is no `c sigma` filter.

The empirical route scale is the weighted central second moment

```text
mu_reach = sum_n w_n Delta_n / sum_n w_n
Sigma_reach = sum_n w_n (Delta_n-mu)(Delta_n-mu)^T / sum_n w_n,
Delta_n = x'_n - x_n.
```

No diagonal inflation, radius multiplier, regularizer, or fitted cutoff is
added.  The build fails if the covariance is not positive definite.

## 4. Acquisition posterior

Let `G` be the unique recorded xy support.  Partition it into axis-aligned
cells of width `sigma`, with the origin fixed at the componentwise minimum of
`G`.  Each occupied cell receives equal prior mass, shared equally by support
points inside that cell.  This corrects collection-density bias without a
spatial bandwidth beyond `sigma`.

The unknown contact radius has the exact prior

```text
p(rho) proportional to 1/rho,
rho in [rho_min, rho_max],
rho_min = sigma,
rho_max = exact Euclidean diameter of G.
```

There is no radius grid.  For each possible goal `g`, the posterior stores the
feasible interval `[lower_g, upper_g)`.  A no-contact observation at `x`
updates `upper_g <- min(upper_g, ||x-g||)`.  Contact ends acquisition, so no
post-contact approximation of this posterior is needed.  Exhausting every
hypothesis is a fatal model-falsification error; there is no fallback field.

For a candidate hub `h`, its exact posterior contact coverage is

```text
C(h) = sum_g p(g | history) P(rho >= ||g-h|| | g, history).
```

Under the log-uniform interval this conditional probability is 1 below the
lower bound, 0 above the upper bound, and

```text
log(upper_g / ||g-h||) / log(upper_g / lower_g)
```

between them.

## 5. Hubs and finite-horizon reachability

The hub bank contains one recorded node per occupied `sigma` cell.  Its size
is therefore data-derived rather than chosen.  Coverage is recomputed after
new evidence.

For each hub, finite-horizon reachability is computed on the same recorded
edges and learned bridges used by the supplied-goal router.  For edge
reliability `w_e`, destination `d_e`, and source `i`, the reachability backup
is

```text
V_0^h(i) = 1[i = h]
V_r^h(i) = max_e { w_e V_(r-1)^h(d_e)
                   + (1-w_e) V_(r-1)^h(i) },
V_r^h(h) = 1.
```

At a live state with `R` commands remaining, TF-SN chooses exactly

```text
h* = argmax_h C(h) R_R(h | current state),
```

where `R_R` includes both levels of online correction below.  The selected hub
is then routed to by the unchanged supplied-goal router.  Passage states are
added to the acquisition evidence, and coverage is recomputed before the next
hub choice.

## 6. Online consequence correction

Online memory persists across physical resets of one task and is cleared
between tasks.  Both correction levels use the same posterior mean:

```text
p_corrected = (p_offline + sum_j K_j y_j) / (1 + sum_j K_j).
```

The `1` is the single global evidence-prior weight.  It means that the offline
model counts as one observation.  It is not retuned by domain.

### 6.1 Link level

For a selected graph destination `d`, the binary outcome is

```text
y = 1[||phi(s') - d|| <= sigma].
```

Evidence transfers continuously with

```text
K_link = exp(-0.5 (
    ||source-source_j||^2 / sigma^2
  + ||command-command_j||^2 / sigma^2
  + ||destination-destination_j||^2 / sigma^2)).
```

There is no neighbour cutoff.  This corrects the probability of reaching the
link destination, not agreement with a sampled model endpoint and not merely
whether the agent moved.

### 6.2 Hub-route level

A route attempt records its start, selected hub, exact remaining-command
horizon, and outcome.  Arrival means entering `sigma` of the hub before the
attempt expires.  Task contact before hub arrival censors the attempt rather
than counting it as a failure.

Evidence transfers only between attempts with the same remaining-command
horizon, using

```text
K_route = exp(-0.5 (
    (source-source_j)^T Sigma_reach^-1 (source-source_j)
  + (hub-hub_j)^T Sigma_reach^-1 (hub-hub_j))).
```

The source and destination sides use the same data-derived covariance.  There
is no route radius or cutoff.

## 7. Return

After first contact, the planner uses the frozen supplied-goal return values
and the link-level destination-arrival correction.  R76--R78 route-return and
online-map-growth diagnostics were rejected and are not part of the frozen
method.  In particular, the hub-route correction is an acquisition mechanism;
it is not silently applied to return.

## 9. Fixed-rule inventory for reviewer 1

There is no hand-set per-environment planner rule.

| Potential source of tuning | Frozen treatment |
|---|---|
| Same-place/arrival scale | `sigma`, learned from held-out consequence data |
| Search radius | Latent; prior bounds are `sigma` and exact support diameter |
| Goal-location prior resolution | Occupied `sigma` cells |
| Hub count and positions | One recorded node per occupied `sigma` cell |
| Route generalization scale | Empirical weighted reach covariance |
| Planning horizon | `H=T/tau` |
| Command duration | One shared global `tau=100` |
| Link/route cutoffs | None |
| Wall avoidance | No wall input or crossing rule |
| Detection/contact radius | Evaluator only; forbidden to planner |
| Candidate shortlist | None for hubs; exact branch-and-bound argmax |
| Online prior strength | One shared prior weight of 1 |
| Environment coordinates | Forbidden |

The environment-specific objects are only adapters and learned artifacts:
state/action schema, executor checkpoint, reward-free trajectories, and the
declared episode budget.  Their numerical consequences differ because the
data differ, while their estimators and decision equations are identical.

## 10. Rebuild and verification

For a clean rebuild:

1. bind the executor checkpoint and its training budget;
2. collect reward-free fixed-`tau` command trajectories;
3. fit the shared consequence ensemble and compute `sigma` on held-out data;
4. build recorded edges, reach candidates, bridges, mobility, and passages;
5. compute the occupied-cell prior, hub bank, support diameter, and
   `Sigma_reach` from the rebuilt artifacts;
6. derive `H=T/tau`;
7. run the specification audit before evaluation; and
8. bind all artifacts and evaluation evidence by SHA-256.
